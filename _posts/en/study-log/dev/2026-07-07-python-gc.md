Garbage collection is the process of cleaning up memory that is no longer used.

Let's look at an example.

```python
a = [1, 2, 3]

# Here, the list object [1,2,3] is created in memory, and a points to it.
# a -> [1,2,3]

a = None

## Now there is no variable pointing to [1,2,3].
```

```python
def test():
    x = [1, 2, 3]
    y = {"name": "hong"}

## In this case, x and y remain alive while the function runs.
## When the function ends, the names x and y disappear, leaving no variables pointing to [1,2,3] or {"name": "hong"}.
```

Objects like these, which nothing points to, are called garbage.

The process of cleaning up that garbage is garbage collection.

Python does most of this automatically. `(Reference Counting + GC)`

That is why we usually do not free memory ourselves.

Python performs garbage collection in two stages.

## Reference Counting

What is reference counting? It means counting how many references point to an object.

```python
a = [1, 2, 3]
b = a

# a ─┐
#    ├──> [1, 2, 3]
# b ─┘

# Reference Count = 2

a = None

# b ──> [1, 2, 3]

# Reference Count = 1

b = None

# [1, 2, 3]

# Reference Count = 0
```

When the reference count reaches 0, the object is immediately removed from memory.

## GC

GC finds objects that reference counting alone cannot clean up and removes them from memory.

A typical example is a **cyclic reference**.

```python
a = []
b = []

a.append(b)
b.append(a)

# a ───> list A ───> list B
#        ↑          │
#        └──────────┘

a = None
b = None

# Here, variables a and b are gone, but list A and list B still point to each other.
```

There are no variables through which we can access them, yet their reference counts are not 0.

---

## Wrapping Up

Python manages garbage collection, or cleaning up unused memory, automatically, so you do not need to manage it yourself.

An object that you continue to reference cannot be removed.

Cyclic references may be cleaned up later.

Resources such as files, connections, and network connections should not be left to GC.
