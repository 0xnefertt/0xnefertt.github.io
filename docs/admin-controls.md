# 관리자에서 관리하는 항목

일상적인 콘텐츠와 사이트 운영 설정은 `/admin/`에서 관리합니다. 사이트를 구성하는 모든 코드가 관리자 입력란으로 바뀌는 구조는 아닙니다.

| 항목                                                                      | 관리자 메뉴 | 반영되는 곳                                                |
| ------------------------------------------------------------------------- | ----------- | ---------------------------------------------------------- |
| 블로그 글, 언어, 번역 연결, 날짜, 태그, 하위 분류, 이미지                 | 글          | 글 목록, 상세 페이지, 검색, RSS, sitemap                   |
| 책장 글, 발행일, 표지 이미지, 번역                                        | 책장        | 책장 목록과 독서 기록                                      |
| 프로젝트 본문, 이미지, 상태, 기간, 역할, 기술, 정렬 순서                  | 프로젝트    | 프로젝트 목록과 상세 페이지                                |
| 자기소개 본문, 이름, 지역, 짧은 소개, 사진, 원형 표시                     | 소개·프로필 | About, 홈 프로필, 글 작성자 정보                           |
| 사이트 이름, 블로그 제목, Email/GitHub/X, 기본 공유 이미지, 홈 최근 글 수 | 사이트 설정 | 헤더, Footer, 페이지 메타데이터, 글의 작성자 링크, 홈      |
| 영어·한국어 블로그 소개                                                   | 블로그 소개 | 홈과 블로그 상단, 기본 검색 설명, RSS                      |
| 영어·한국어 Resources 소개, 날씨 지역/좌표, 통화, Useful Info 표시 여부   | Resources   | `/resources/`, `/ko/resources/`                            |
| 영어·한국어 개인정보 안내 본문                                            | Privacy     | `/privacy/`, `/ko/privacy/`; 본문 변경 시 수정일 자동 갱신 |
| 영어·한국어 카테고리 이름과 순서                                          | 카테고리    | 메뉴, 글 분류와 목록; 주소는 유지                          |
| 즐겨찾기 그룹, 링크, 설명과 순서                                          | 즐겨찾기    | Resources                                                  |

글 초안은 비공개 자동 저장을 사용합니다. 사이트 설정은 공유 작업 사본을 사용하며 **저장하고 반영**을 눌러야 공개 설정 파일과 사이트가 갱신됩니다.
다른 곳에서 설정을 먼저 수정했다면 기존 버전 검사로 덮어쓰기를 차단합니다. 이전 관리자 탭이 새 설정 필드를 보내지 않아도 이미 저장한 값은 보존합니다.

## 코드·환경 설정으로 유지하는 항목

- 도메인과 canonical origin, 영문 루트·한국어 `/ko/` 라우팅, 메뉴 순서와 기능별 UI 번역
- 화면 배치, CSS, 폰트, 파비콘 파일, 공유·검색·목차 등의 기능
- GitHub 소유자 인증, 저장소/브랜치, OAuth 자격 증명, Cloudflare/D1, 배포 워크플로
- Analytics, AdSense, Giscus의 환경 변수와 외부 서비스 API 주소
- 기존 외부 링크형 글과 경로·분류 호환 규칙. 외부 링크형 글은 저장소에서 직접 관리합니다.

이 설정을 일반 콘텐츠 편집으로 취급하면 인증이나 사이트 주소를 잘못 바꿀 수 있으므로 관리자 콘텐츠 저장과 분리합니다.

## 정리한 중복과 잔여 코드

- Footer와 Privacy 이메일, 글 작성자의 소셜 링크는 `_data/site-settings.json`의 연락처를 공유합니다.
- 별도 `_data/socials.yml`과 전용 YAML 문자열 파서는 제거했습니다.
- Resources는 About 문서에 숨어 있던 날씨·환율 설정을 더 이상 읽지 않습니다. 기존 메타데이터는 글·초안 보존을 위해 유지합니다.
- 사이트명과 Footer 저작권 문구, 블로그 제목, 기본 메타데이터에 개인 문자열을 별도로 반복하지 않습니다.
- 프로필 값이 없을 때 임의의 지역이나 소개 글을 만들어 표시하던 기본값을 제거했습니다.
- 이미 제거한 책 별점 입력을 위한 분기와 중복 메뉴 번역 처리를 제거했습니다.
- `_data/site-defaults.json`은 이전 설정 파일을 읽기 위한 호환 기본값입니다. 실제 운영 값은 `_data/site-settings.json`에서 읽고 관리자에서 변경합니다.

## 발행 취소와 이미지 관리

글·책·프로젝트의 작업본에서 **발행 취소**를 누르면 공개 원본에 `draft: true`를 기록합니다.
배포가 완료되면 목록, 상세 경로, 검색, RSS, sitemap에서 제외됩니다. 작업본과 기존 주소는 유지되며 **다시 발행**으로 복구할 수 있습니다.
소개·프로필에는 발행 취소를 제공하지 않습니다. 초안 휴지통과 발행 취소는 별개입니다.
이미 공개된 원본·Git 기록·공개 이미지와 외부 검색 캐시는 남으므로 민감한 정보의 영구 삭제나 비공개 보관 기능으로 사용하지 마세요.

**첨부 이미지 관리**에서 작업본의 첨부 수·용량·사용 여부를 확인하고 미사용 이미지를 삭제할 수 있습니다.
본문·표지·프로필 등 저장된 문서에 참조가 있거나 다른 기기에서 수정했거나 발행 중이면 삭제를 거절합니다.
이미지의 D1 데이터와 모든 조각을 함께 삭제하고 작업본 버전을 올립니다. 삭제한 슬롯은 다시 첨부할 수 있습니다.
공개 저장소 이미지는 건드리지 않으며 비공개 첨부 삭제는 영구적입니다.

## 검사와 배포

`npm run verify`는 루트·Astro·writer 의존성 감사, 전체 소스 포맷, 콘텐츠, Astro·writer 타입, 관리자 테스트, 빌드와 출력 검사를 실행합니다.
Astro 소스도 포맷 검사에 포함하고 빌드 출력·생성 타입만 제외합니다. 루트와 발행 API는 같은 Prettier 버전을 사용합니다.
Astro 7.3.8과 관련 전이 의존성 업데이트 후 2026-10-11 조회 기준 세 패키지의 npm audit 경고는 0건입니다. 감사는 각 실행 시 다시 조회합니다.

`Deploy site`는 검증된 결과물을 보관하고, writer/shared/호환 기본값이 바뀌면 D1 마이그레이션 → Worker 배포 → 공개 사이트 배포 순서로 진행합니다.
Worker 배포 실패 시 공개 사이트 배포도 중단합니다. 글이나 운영 설정만 바뀐 경우 Worker 재배포는 생략합니다.
자동 배포에는 해당 Cloudflare 계정의 Worker 배포 및 D1 접근 권한을 가진 `CLOUDFLARE_API_TOKEN` 저장소 secret이 필요합니다.
2026-10-11 `nefertt-writer-github-actions` 토큰을 `CLOUDFLARE_API_TOKEN` 저장소 secret으로 등록했습니다.
대상은 `0xnefertt` 계정이며 Workers Scripts Edit와 D1 Edit만 포함합니다. 다른 계정과 계정 설정 권한은 포함하지 않습니다.
토큰은 채팅이나 저장소 파일에 넣지 말고 GitHub Actions secret으로 관리하세요.
수동 실행에서 Worker 배포를 생략하려면 동일 버전의 API를 이미 별도로 배포한 경우에만 `deploy_writer`를 끄세요.
이번 기능은 기존 D1 스키마를 사용하므로 새 마이그레이션은 필요하지 않습니다.

초안·이미지 전체 백업, 복구 검증과 브라우저 검사 절차는 [백업·복구 안내](writer-recovery.md)를 참고하세요.
